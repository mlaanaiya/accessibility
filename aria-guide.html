Principes fondamentaux

Accessible Rich Internet Applications (ARIA) comble les limites de HTML lorsqu’il est nécessaire de décrire une interaction complexe. Utilisez ARIA pour ajouter des informations que le HTML natif ne permet pas d’exprimer, jamais pour remplacer un élément sémantique existant.

Règle absolue : First rule of ARIA — n’utilisez ARIA que lorsque le HTML natif est insuffisant. Les composants natifs (boutons, liens, champs de formulaire, titres) restent prioritaires.

  • Chaque rôle implique un patron de clavier à respecter (Tab, flèches, barre d’espace, Entrée, Échap).
  • Chaque rôle doit être accompagné des états requis (par ex. aria-expanded sur un accordéon).
  • Les identifiants utilisés par ARIA (aria-labelledby, aria-controls, etc.) doivent rester uniques et synchronisés.
  • Le contenu modifié dynamiquement doit être signalé via aria-live ou les rôles adéquats.

Rôles de repère (Landmarks)

Les repères structurent la page et permettent la navigation rapide via les lecteurs d’écran. Assignez-les à une balise native ou à un <div> lorsque aucune alternative n’existe.

Landmarks essentiels
Rôle Quand l’utiliser Bonnes pratiques Exemple
banner En-tête principal du site, unique par page. Utiliser <header> au niveau racine. <header role="banner">...</header>
navigation Sections contenant des liens de navigation. Préciser le contexte via aria-label (ex. navigation principale). <nav aria-label="Navigation secondaire">...</nav>
main Zone de contenu principal, une seule occurrence. Encadrer le contenu central et définir un id cible du lien d’évitement. <main id="contenu">...</main>
complementary Contenu secondaire lié (ex. aside, encadré). Nommer la zone avec aria-label pour clarifier sa fonction. <aside role="complementary" aria-label="Fil d'actualités">...</aside>
contentinfo Informations légales et de bas de page. Utiliser <footer> du site (pas d’un article interne). <footer role="contentinfo">...</footer>
search Bloc de recherche global ou local. Associer <form role="search"> et définir un titre explicite. <form role="search" aria-label="Recherche catalogue">...</form>
region Zone importante non couverte par les rôles précédents. Obligatoirement accompagné de aria-label ou aria-labelledby. <section role="region" aria-labelledby="faq">...</section>

Structure documentaire

Les rôles de structure complètent la sémantique HTML pour définir des composants logiques (article, complément, note, etc.). Privilégiez les balises HTML (<article>, <aside>, <figure>) puis appliquez ARIA uniquement si nécessaire.

  • article — Contenu indépendant (ex. actualité, fiche produit). Balise native recommandée.
  • figure + figcaption — Alternative sémantique à role="figure".
  • note — Encadrés informatifs ; à associer à un titre.
  • presentation — Supprime la valeur sémantique (utilisation très rare, risques élevés).
  • application — Réservé aux interfaces très riches qui gèrent elles-mêmes la navigation clavier. À utiliser avec parcimonie.

Widgets interactifs & patrons clavier

Les widgets ARIA doivent reproduire le comportement clavier d’un composant natif. Chaque rôle s’accompagne d’une liste d’états requis.

Rôles de widgets usuels
Rôle Usage Clavier attendu Attributs requis
button Action ponctuelle. Privilégier <button>. Espace / Entrée. aria-pressed si bouton à état.
menu & menuitem Menus contextuels au clavier. Flèches pour naviguer entre les items, Échap pour fermer. aria-haspopup, aria-expanded, aria-controls.
tablist/tab/tabpanel Onglets liés à des panneaux de contenu. Flèches gauche/droite, Home/End, Tabulation pour entrer dans le panneau. aria-selected, aria-controls, aria-labelledby.
dialog / alertdialog Fenêtre modale (dialogue) ou alerte importante. Échap pour fermer, le focus reste piégé dans la modale. aria-modal="true", gestion du focus initial/final.
slider Contrôles de plage (volume, luminosité). Flèches, Home/End, Page Up/Page Down. aria-valuenow, aria-valuemin, aria-valuemax, aria-labelledby.
progressbar Indicateur de progression. Non focusable sauf si interactif. Lecture seule. aria-valuemin, aria-valuemax, aria-valuenow.

Astuce : Inspirez-vous des WAI-ARIA Authoring Practices pour implémenter le comportement clavier et les attributs requis.

Régions vivantes et annonces dynamiques

Les live regions informent les utilisateurs des changements asynchrones sans déplacer le focus. Choisissez le niveau d’importance adéquat.

Live regions & rôles d'annonce
Rôle / Attribut Scénario Niveau d’annonce Exemple
aria-live="polite" Confirmations non critiques (sauvegarde, message d’info). Annonce après la parole en cours. <p aria-live="polite">Profil sauvegardé</p>
aria-live="assertive" Alertes critiques (erreur bloquante, perte de connexion). Annonce immédiate, interrompt la lecture. <div aria-live="assertive" role="alert">Session expirée</div>
role="status" Feedback passif (chargement terminé, ajout au panier). Polite implicite. <div role="status">5 résultats trouvés</div>
role="alert" Erreurs critiques à corriger immédiatement. Assertive implicite. <div role="alert">Carte refusée</div>
role="log", role="timer", role="marquee" Flux d’informations continus (console, chronomètre). Dépend de aria-live, aria-relevant. <div role="log" aria-live="polite" aria-relevant="additions">...</div>

États et propriétés ARIA

Attributs globaux

Disponibles pour la plupart des rôles. Ils complètent l’information accessible.

  • aria-label — Décrit un élément lorsque aucun texte visible n’est disponible.
  • aria-labelledby — Préférable à aria-label pour réutiliser un texte existant.
  • aria-describedby — Ajoute une aide ou un message supplémentaire (formulaires, composants).
  • aria-hidden — Masque l’élément aux aides techniques. Ne jamais l’utiliser sur un élément focusable.
  • aria-busy — Indique qu’une section est en cours de mise à jour.

États des widgets

États nécessaires pour les interactions
Attribut Description Exemple d’usage
aria-expanded Indique si un panneau est ouvert ou fermé. <button aria-expanded="false" aria-controls="faq-1">FAQ</button>
aria-selected Sélection dans les listes d’onglets, options, listebox. <button role="tab" aria-selected="true">Vue 1</button>
aria-pressed Etat binaire des boutons toggles. <button aria-pressed="true">Afficher la grille</button>
aria-checked Etat des cases à cocher personnalisées. <div role="checkbox" aria-checked="false" tabindex="0">Activer les alertes</div>
aria-current Marque l’élément représentant l’étape courante (navigation, pagination). <a aria-current="page" href="/tableau-de-bord">Tableau de bord</a>
aria-haspopup Signale l’ouverture d’un sous-menu, d’une liste ou d’un dialogue. <button aria-haspopup="menu" aria-expanded="false">Filtres</button>

Relations et navigation

  • aria-controls — Référence l’élément contrôlé (accordéons, onglets, menus).
  • aria-owns — Définit une relation parent/enfant logique lorsque le DOM ne le permet pas (rare).
  • aria-activedescendant — Gère le focus virtuel (listbox, combobox). Doit pointer vers un élément focusable.
  • aria-details — Lien vers une description complémentaire détaillée.
  • aria-errormessage — Message d’erreur associé à un champ, en plus de aria-describedby.

Tests, diagnostics et ressources

Les attributs ARIA doivent être testés avec des lecteurs d’écran (NVDA, JAWS, VoiceOver), la navigation clavier et des outils automatisés (axe-core, Lighthouse). Documentez les rôles et états dans vos revues de code.

Checklist d’intégration

  • Les rôles correspondent-ils au motif WAI-ARIA ?
  • Les attributs aria-* pointent-ils vers des identifiants valides ?
  • La navigation clavier respecte-t-elle l’ordre logique ?
  • Une alternative HTML native existe-t-elle ?
