Architecture inclusive

Structure du projet

  • Utiliser les standalone components pour limiter l’encombrement des modules.
  • Segmenter les layouts (ShellComponent) et les pages fonctionnelles (FeatureComponent).
  • Mettre en place un AccessibilityService pour centraliser annonces, focus, raccourcis.

Routing & titres

  • Injecter Title et Meta pour mettre à jour le titre & la description à chaque navigation.
  • Utiliser ViewportScroller pour ramener le focus sur le contenu principal.
  • Configurer des routes accessibles (lien d’évitement, aria-current sur les liens actifs).
import { Injectable, inject } from '@angular/core';
import { Title } from '@angular/platform-browser';
import { LiveAnnouncer } from '@angular/cdk/a11y';

@Injectable({ providedIn: 'root' })
export class AccessibilityService {
  private readonly title = inject(Title);
  private readonly liveAnnouncer = inject(LiveAnnouncer);

  setPageTitle(label: string): void {
    this.title.setTitle(`Académie RGAA — ${label}`);
  }

  announce(message: string, politeness: 'polite' | 'assertive' = 'polite'): void {
    this.liveAnnouncer.announce(message, politeness);
  }
}

Templates & composants accessibles

Gestion du focus

Injectez FocusMonitor pour suivre le mode d’interaction (clavier/souris) et appliquez vos styles de focus.

import { Component, ElementRef, OnDestroy } from '@angular/core';
import { FocusMonitor } from '@angular/cdk/a11y';

@Component({
  selector: 'app-primary-button',
  template: `<button class="btn btn--primary"><ng-content></ng-content></button>`
})
export class PrimaryButtonComponent implements OnDestroy {
  constructor(private fm: FocusMonitor, private el: ElementRef<HTMLElement>) {
    this.fm.monitor(this.el.nativeElement, true).subscribe(origin => {
      if (origin === 'keyboard') {
        this.el.nativeElement.classList.add('focus-ring');
      } else {
        this.el.nativeElement.classList.remove('focus-ring');
      }
    });
  }

  ngOnDestroy(): void {
    this.fm.stopMonitoring(this.el.nativeElement);
  }
}

Composants personnalisés

  • Exposez des attributs ARIA au niveau du composant (@HostBinding('attr.aria-expanded')).
  • Supportez les événements clavier (@HostListener sur Enter/Space).
  • Fournissez du texte alternatif via @Input() et aria-label.
import { Component, EventEmitter, HostBinding, HostListener, Input, Output } from '@angular/core';

@Component({
  selector: 'app-toggle',
  template: `
    <span class="toggle__handle" [class.toggle__handle--on]="pressed"></span>
    <span class="visually-hidden">{{ label }}</span>
  `,
  host: {
    role: 'button',
    tabindex: '0'
  }
})
export class ToggleComponent {
  @Output() readonly changed = new EventEmitter<boolean>();
  @Input() label = 'Activer la fonction';
  @HostBinding('attr.aria-pressed') pressed = false;
  @HostBinding('attr.aria-label') get ariaLabel(): string {
    return this.label;
  }

  @HostListener('click')
  @HostListener('keydown.enter')
  @HostListener('keydown.space', ['$event'])
  toggle(event?: KeyboardEvent): void {
    if (event) {
      event.preventDefault();
    }
    this.pressed = !this.pressed;
    this.changed.emit(this.pressed);
  }
}

Formulaires réactifs accessibles

Principes :

  • Associer chaque label à un formControlName.
  • Afficher les erreurs sous le champ avec aria-describedby et aria-live="polite".
  • Gérer le focus sur la première erreur après soumission.
import { Component, ElementRef, QueryList, ViewChildren, inject } from '@angular/core';
import { FormBuilder, Validators } from '@angular/forms';

@Component({
  selector: 'app-signup-form',
  templateUrl: './signup-form.component.html'
})
export class SignupFormComponent {
  private readonly fb = inject(FormBuilder);
  @ViewChildren('field') private fields!: QueryList<ElementRef<HTMLElement>>;

  readonly form = this.fb.group({
    email: ['', [Validators.required, Validators.email]],
    password: ['', [Validators.required, Validators.minLength(12)]],
    updates: [false]
  });

  submit(): void {
    if (this.form.invalid) {
      const invalid = this.fields.find(field => field.nativeElement.getAttribute('aria-invalid') === 'true');
      invalid?.nativeElement.focus();
      return;
    }
    // Traitement API & annonce accessibilité
  }
}
<form [formGroup]="form" (ngSubmit)="submit()" novalidate>
  <div class="form-field">
    <label for="signup-email">Adresse électronique</label>
    <input
      #field
      id="signup-email"
      type="email"
      formControlName="email"
      [attr.aria-invalid]="form.controls.email.invalid"
      aria-describedby="signup-email-erreur"
      autocomplete="email"
      required
    />
    <p
      id="signup-email-erreur"
      class="form-error"
      aria-live="polite"
      *ngIf="form.controls.email.invalid && form.controls.email.touched"
    >
      Fournissez une adresse valide.
    </p>
  </div>

  <div class="form-field">
    <label for="signup-password">Mot de passe</label>
    <input
      #field
      id="signup-password"
      type="password"
      formControlName="password"
      minlength="12"
      [attr.aria-invalid]="form.controls.password.invalid"
      aria-describedby="signup-password-help signup-password-erreur"
      required
    />
    <p id="signup-password-help" class="form-hint">
      12 caractères minimum, inclure majuscules/minuscules et chiffre.
    </p>
    <p
      id="signup-password-erreur"
      class="form-error"
      aria-live="assertive"
      *ngIf="form.controls.password.invalid && form.controls.password.touched"
    >
      Mot de passe incomplet : complétez les exigences.
    </p>
  </div>

  <label class="checkbox">
    <input type="checkbox" formControlName="updates" />
    Recevoir des actualités accessibilité
  </label>

  <button type="submit" class="btn btn--primary">Créer le compte</button>
</form>

Angular Material & CDK

Personnaliser le thème

  • Utiliser mat.define-dark-theme avec des contrastes supérieurs à 4.5:1.
  • Activer les density tokens pour augmenter la taille des zones cliquables.
  • Remplacer les icônes purement visuelles par mat-icon + texte caché.

CdkTrapFocus & LiveAnnouncer

  • Utiliser cdkTrapFocus dans les modales/menus.
  • Utiliser cdkFocusInitial pour poser le focus dès l’ouverture.
  • Annoncer les changements via LiveAnnouncer ou FocusMonitor.
@Component({
  selector: 'app-confirm-dialog',
  template: `
    <h2 id="dialog-title" mat-dialog-title>Confirmer l'action</h2>
    <div mat-dialog-content>
      <p>Cette modification affectera la roadmap accessibilité.</p>
    </div>
    <div mat-dialog-actions>
      <button mat-stroked-button mat-dialog-close>Annuler</button>
      <button mat-flat-button color="accent" cdkFocusInitial (click)="confirm()">Valider</button>
    </div>
  `,
  host: {
    role: 'dialog',
    'aria-modal': 'true',
    'aria-labelledby': 'dialog-title',
    cdkTrapFocus: ''
  }
})
export class ConfirmDialogComponent {
  constructor(private accessibility: AccessibilityService) {}

  confirm(): void {
    this.accessibility.announce('Action confirmée', 'assertive');
  }
}

Tests automatisés & CI/CD

axe-core dans Cypress

import 'cypress-axe';

describe('Dashboard accessibilité', () => {
  beforeEach(() => {
    cy.visit('/dashboard');
    cy.injectAxe();
  });

  it('doit être conforme', () => {
    cy.checkA11y(null, {
      includedImpacts: ['critical', 'serious']
    });
  });
});

Pipeline recommandé :

  1. Linting avec @angular-eslint (règles template/accessibility).
  2. Tests unitaires (Jest/Karma) incluant snapshot ARIA (fixture.debugElement.attributes).
  3. Tests end-to-end Cypress + axe.
  4. Lighthouse CI pour l’accessibilité de production.
