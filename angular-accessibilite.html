Architecture accessible dès la conception

Angular permet de structurer l’application autour de composants autonomes, d’un routage maîtrisé et d’un cycle de déploiement industriel. Intégrer l’accessibilité dès la conception réduit drastiquement la dette a11y.

  • Structure modulaire : adopter les standalone components et modules fonctionnels pour isoler les responsabilités et réutiliser les patrons accessibles.
  • Routage : définir des titres de page dynamiques (service Title), gérer le retour en haut de page (ViewportScroller), annoncer les changements de route (LiveAnnouncer).
  • Gestion d’état : préférer un store observable (signals, RxJS) qui facilite la synchronisation des messages accessibles.
  • Performance : le change detection optimisé (OnPush, signal-based) réduit les re-rendus superflus et offre une expérience fluide.

Objectif : chaque fonctionnalité Angular doit disposer d’un contrat accessibilité (focus, annonces dynamiques, navigation clavier).

Templates & composants accessibles

Les templates Angular doivent conserver la sémantique HTML et relier les attributs ARIA aux données dynamiques. Utilisez les directives du CDK pour hiérarchiser le focus et annoncer les changements.

Gestion du focus

<button cdkFocusInitial (click)="openDialog()">
  Créer un compte
</button>

<div
  cdkTrapFocus
  cdkTrapFocusAutoCapture
  class="dialog"
  role="dialog"
  aria-modal="true"
  aria-labelledby="dialog-title"
>
  <h2 id="dialog-title">Confirmation</h2>
  <p>Votre profil a été mis à jour.</p>
  <button (click)="close()" cdkFocusInitial>Fermer</button>
</div>
  • cdkFocusInitial définit le focus initial à l’ouverture.
  • cdkTrapFocus empêche le focus de sortir du dialogue tant qu’il est actif.
  • aria-modal, aria-labelledby et un bouton de fermeture clavier garantissent l’utilisabilité.

Annonces dynamiques

import { Component } from '@angular/core';
import { LiveAnnouncer } from '@angular/cdk/a11y';

@Component({
  selector: 'app-notifications',
  template: `
    <button (click)="notify()">Ajouter au panier</button>
    <p aria-live="polite">{{ message }}</p>
  `,
})
export class NotificationsComponent {
  message = '';
  constructor(private liveAnnouncer: LiveAnnouncer) {}

  notify(): void {
    this.message = 'Produit ajouté au panier.';
    this.liveAnnouncer.announce(this.message, 'polite');
  }
}

Le LiveAnnouncer synchronise le feedback vocal tout en laissant le message visible.

Formulaires réactifs

<form [formGroup]="profileForm" novalidate>
  <label for="email">Adresse e-mail</label>
  <input
    id="email"
    type="email"
    formControlName="email"
    aria-describedby="email-help email-error"
    [attr.aria-invalid]="email.invalid &&#38; email.touched"
  />
  <span id="email-help">Format attendu : prenom.nom@domaine.fr</span>
  <span id="email-error" *ngIf="email.errors" role="alert">
    Adresse invalide
  </span>
</form>

Associez systématiquement aides et erreurs via aria-describedby et role="alert".

Angular Material & CDK : personnalisation accessible

Angular Material repose sur le CDK (Component Dev Kit) qui fournit des primitives accessibilité. Personnalisez votre design system sans perdre les garanties a11y.

  • Thèmes : contrôlez les contrastes via les tokens mat.define-light-theme et mat.define-dark-theme.
  • Tableaux : ajoutez scope, aria-sort et un résumé via <caption>.
  • Snackbars & dialogues : combinez MatSnackBar avec LiveAnnouncer et MatDialog avec FocusTrap.
  • CDK A11y : FocusMonitor, ListKeyManager et ActiveDescendantKeyManager facilitent la gestion des interactions clavier complexes.

Tests, CI/CD et surveillance continue

Automatisez les vérifications accessibilité à chaque étape du pipeline Angular pour détecter rapidement les régressions.

  • Unitaires : Jasmine/Karma + axe-core, snapshot des attributs ARIA.
  • End-to-end : Cypress + cypress-axe ou Playwright + @axe-core/playwright.
  • CI/CD : GitHub Actions ou GitLab CI avec job dédié (npm run lint -- --config .eslintrc-a11y.json, npm run test:a11y).
  • Monitoring : Lighthouse CI, Pa11y, Purple HATS pour suivre les régressions après déploiement.

Checklists & ressources

Checklist « feature »

  • Arborescence de titres correcte (h1 unique).
  • Composants interactifs utilisables au clavier et annoncés.
  • Focus visible, piège de focus impossible.
  • Messages d’erreur reliés aux champs et annoncés.
